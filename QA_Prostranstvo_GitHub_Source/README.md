# QA Пространство — исходники для GitHub Pages

Это **полная версия сайта, разделённая на файлы**, включая публичное подключение к Supabase. Сборка и установка зависимостей не нужны.

## Как загрузить в GitHub

1. Распакуйте архив на компьютер.
2. Откройте существующий репозиторий **QA_prostranstvp** на GitHub → Code → Add file → Upload files.
3. Загрузите **содержимое папки** `QA_Prostranstvo_GitHub_Source`, а не сам ZIP: `index.html`, `css/`, `js/`, `data/`, `assets/` (папку `database/` публиковать не обязательно).
4. Нажмите **Commit changes**. Убедитесь, что `index.html` находится в корне репозитория, а папки сохранили структуру.
5. GitHub → Settings → Pages: выберите `Deploy from a branch`, `main`, `/(root)`. Подождите завершения Actions/Pages. Откройте сайт с Ctrl+F5.

**Внимание:** на GitHub лучше загружать через GitHub Desktop или `git`, чтобы точно сохранить структуру вложенных папок. При загрузке через веб-интерфейс убедитесь, что папки не расплющились.

## Где что менять

- `index.html` — основная HTML-разметка.
- `css/styles.css` — цвета, шрифты, карточки, мобильная версия.
- `css/cloud.css` — внешний вид облачного входа.
- `data/curriculum.js` — **все уроки, задания, вопросы и шаблоны**. Меняйте тексты, но сохраняйте `id` уроков, если уже есть прогресс пользователей.
- `js/app.js` — страницы, поиск, тесты, локальный прогресс.
- `js/cloud.js` — вход, синхронизация, кабинет преподавателя.
- `js/config.js` — **публичные** Project URL и Publishable key Supabase. Они уже заполнены для проекта QA_Learn.
- `assets/` — иллюстрация и шрифты.
- `database/make_admin.sql` — создание роли администратора в Supabase. Выполнять в Supabase SQL Editor, а НЕ добавлять в HTML или GitHub Pages.

## Настройка Supabase

1. В Supabase → Authentication → URL Configuration: `Site URL` и разрешённый `Redirect URL`: `https://muminovamaftuna.github.io/QA_prostranstvp/`.
2. В Authentication → Providers убедитесь, что включён Email. Массовая рассылка кодов/писем может требовать своего SMTP.
3. Таблицы и функции должны быть созданы **в Supabase**, скриптом `setup.sql`, который запускали ранее. `Success. No rows returned` означает успешное выполнение SQL, но желательно проверить таблицы и тестовый вход.
4. Войдите на сайт под своей почтой и выполните `database/make_admin.sql` в Supabase SQL Editor, указав эту почту.
5. Протестируйте вход и сохранение одного теста, затем проверьте его в базе и кабинете преподавателя.

## Безопасность

`js/config.js` содержит **публичный** ключ. Не добавляйте `sb_secret_...`, `service_role` и пароль базы в GitHub. Надёжность разграничения доступа зависит от RLS и серверных функций в Supabase.

## Проверка

Можно открыть `index.html` напрямую из папки после распаковки; на GitHub Pages сайт должен работать через обычные относительные пути. Сохранение в облаке требует доступа к интернету и правильной настройки Supabase.
